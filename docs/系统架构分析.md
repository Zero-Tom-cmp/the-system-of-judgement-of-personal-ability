# 人岗匹配评估系统 · 系统架构分析

> 用途：功能架构图的设计依据。给出模块划分、颜色分配、各模块功能、模块间相关性、角色设计。
> 配套图：`docs/功能架构图.html`（浏览器打开）

---

## 一、模块划分总览

系统按**职责边界**划分为 **8 个模块**，其中 1–7 为业务模块，8 为支撑模块。
每个模块分配一个**饱和原色**，用于架构图着色（模块间颜色互不相同，同模块内用深浅区分层级）。

| # | 模块 | 代号 | 主色 | 色值 | 一句话职责 |
|---|---|---|---|---|---|
| 1 | 认证权限中心 | AUTH | 青 | `#12A3B4` | 解决「你是谁、你能看什么」 |
| 2 | 数据导入中心 | IMPORT | 橙 | `#F5821F` | 解决「数据怎么批量进来」 |
| 3 | 学生数据中心 | DATA | 绿 | `#1FA85C` | 解决「数据怎么存、怎么管」 |
| 4 | 培养方案中心 | PLAN | 紫 | `#8E44C4` | 解决「按什么标准评」 |
| 5 | 能力评估中心 | EVAL | 蓝 | `#2E75D6` | 解决「能力分怎么算」 |
| 6 | 岗位匹配中心 | MATCH | 红 | `#E8453C` | 解决「适合什么岗位」 |
| 7 | 简历输出中心 | RESUME | 玫红 | `#D6389A` | 解决「结果怎么带走」 |
| 8 | 系统支撑中心 | SYS | 灰蓝 | `#5B7C99` | 解决「系统怎么配、怎么管」 |

**配色逻辑**：1–7 沿「数据流入 → 存储 → 标准 → 计算 → 匹配 → 输出」的业务主线，
色相从冷（青）走到暖（红/玫红）再回到中性（灰蓝），读者可凭颜色直接判断该模块处于流水线的哪一段。

## 二、各模块功能与作用

### 1. 认证权限中心（AUTH · 青）

**作用**：整个系统的唯一入口与安全边界。所有请求先经过此模块，再进入业务逻辑。

| 功能 | 实现位置 | 说明 |
|---|---|---|
| 用户登录认证 | `POST /api/login` | bcrypt 校验密码哈希，学生与管理员共用一张 `students` 表，靠 `role` 字段区分 |
| JWT 令牌签发 | `create_token()` | 载荷含 `student_id` / `role` / `exp`，有效期 7 天 |
| 令牌校验 | `verify_token()` | 每次请求校验签名，失败返回 401 |
| 双层角色鉴权 | `require_admin()` | 管理员放行；学生仅当 `payload.student_id == 目标 id` 时放行，否则 403 |
| 前端路由守卫 | `PrivateRoute` (App.jsx) | 按 `localStorage.role` 拦截，未登录跳回登录页 |
| 密码修改 | `PUT /api/student/password` | 学生自助改密，校验旧密码 |
| 密码重置 | `POST /api/admin/students/batch-reset-pwd` | 管理员批量重置 |

> **设计要点**：权限判定在**后端**完成，前端守卫只负责体验（跳转），不承担安全职责。

---

### 2. 数据导入中心（IMPORT · 橙）

**作用**：把 Excel/CSV 中的批量数据安全地灌入系统，是数据的**主要入口**。

| 功能 | 实现位置 | 说明 |
|---|---|---|
| Excel 一体化导入 | `POST /api/admin/import/all` | 一个文件含学生+课程+竞赛+实习+项目多个 sheet |
| 分模块 CSV 导入 | `POST /api/admin/import/{data_type}` | 按数据类型逐类导入 |
| 导入模板下载 | `GET /api/admin/template/all`、`/{data_type}` | 生成带表头的空模板，CSV 带 BOM 防 Excel 乱码 |
| 学号查重校验 | 数据库 `UNIQUE` 约束 | 学号 / (学生,课程名) / (学生,竞赛名) / (学生,项目名) 唯一 |
| 冲突检测 | 导入流程 | 同一学号出现不同数据 → 判定冲突，**整体拒绝**该条 |
| 冲突数据下载 | `POST /api/admin/import/conflicts/download` | 冲突行落盘 `conflicts/`，管理员可下载排查 |
| 异常兜底 | 事务 + 日志 | 导入中断不写半截数据；失败原因写入日志 |

> **设计要点**：冲突采取「**拒绝 + 可下载**」而非「静默覆盖」，保证数据可追溯。

---

### 3. 学生数据中心（DATA · 绿）

**作用**：系统的**唯一数据源**，承载学生的全部在校数据，供评估、匹配、简历三个下游模块消费。

管理 5 类核心数据（对应 5 张表）：

| 数据类 | 数据表 | 字段要点 |
|---|---|---|
| 基本信息 | `students` | 学号、姓名、学院、专业、班级、GPA、英语证书（类型+分数） |
| 课程成绩 | `courses` | 课程名、成绩、学分、**实践学分**、学期、课程性质 |
| 竞赛获奖 | `competitions` | 竞赛名、级别（国家/省级）、奖项、**队内排名**、时间 |
| 企业实习 | `internships` | 企业、岗位、描述、**起止时间** |
| 项目经历 | `projects` | 项目名、**队内排名**、描述、起止时间 |

配套管理能力：

| 功能 | 说明 |
|---|---|
| 增删改查 | 5 类数据各有一套 REST 接口，管理员可编辑 |
| 检索筛选 | 按 学院 / 专业 / 班级 / 姓名 / 学号 组合筛选，按学号排序 |
| 批量操作 | 批量删除、批量重置密码 |
| 数据总览 | 学生总数、专业分布等统计指标 |

---

### 4. 培养方案中心（PLAN · 紫）

**作用**：定义「**评分标准**」。不同专业培养方案不同，本模块提供差异化评判依据。

| 功能 | 数据表 | 说明 |
|---|---|---|
| 培养方案存储 | `training_plan` | 按专业（主键）存 JSON，含毕业要求与课程体系 |
| 毕业要求—课程体系矩阵 | `training_plan.plan_data` | 展示「课程 → 支撑哪条毕业要求」的 H/M 对应关系 |
| 能力维度定义 | `ability_config` | 每个专业定义若干能力维度（如软件工程 6 维、金融学 6 维） |
| 课程→能力映射 | `course_ability_mapping` | 每门课对哪些能力维度有贡献、贡献权重多少 |
| 专业权重配置 | `ability_config.weight` | 各维度在本专业内的相对重要性 |

> **设计要点**：**标准与算法分离**。评估引擎不含任何专业特定常量，换专业只改数据不改代码。

---

### 5. 能力评估中心（EVAL · 蓝）

**作用**：系统**核心算法模块之一**。把 5 类原始数据换算成 0–100 的能力分。

**评估链路**（5 个数据源 → 加权贡献 → 归一化 → 百分制）：

| 数据源 | 贡献上限 | 计算要点 |
|---|---|---|
| 课程 | ~40 | `(成绩/100) × 映射权重 × 学分占比 × 40`，**受学分摊薄** |
| 竞赛 | ~15 | `(级别分 × 奖项分 / 满分) × 映射权重 × 15`，可超额 |
| 企业实习 | ~10 | 按企业层次加权 |
| 项目经历 | ~10 | 按队内排名系数加权 |
| 英语证书 | 15 | 按 CET4/6、雅思、托福**档位**换算，**不受学分摊薄** |

**关键设计**：

- **归一化**（`ability_score.py`）：`s = min(1, raw / 40)`。能力分只表达「该维度有多强」，**不乘权重**——权重统一交给匹配公式，一个概念只出现一次。
- **得分溯源**（`ScoreExplain.jsx`）：每个维度可展开查看「哪几门课/哪个竞赛贡献了多少分」，用最大余额法保证**明细之和 = 合计**。
- **可视化**：雷达图（`AbilityRadar.jsx`）直观呈现各维度强弱。

---

### 6. 岗位匹配中心（MATCH · 红）

**作用**：系统**核心算法模块之二**。把能力分与岗位要求比对，得出匹配度并给出改进方向。

**测算公式**（参考论文《基于AHP-模糊综合评价的人才岗位匹配度测算》，并修正了论文正文的笔误）：

| 步骤 | 公式 | 说明 |
|---|---|---|
| 单因素匹配度 | `m_i = 1 − \|s_i − r_i\|` | 学生能力与岗位要求的**接近程度** |
| 综合匹配度 | `D = Σ e_i · m_i` | `e_i` 为归一化权重 |
| 百分制得分 | `Score = 100 · D` | 最终匹配分 |
| 硬性门槛（扩展） | `D_final = D · Π g_j` | 一票否决项，默认关闭 |

| 功能 | 说明 |
|---|---|
| 岗位能力模型 | `job_ability_profile`：岗位对各能力维度的**要求值** + **重要度权重** |
| 匹配度测算 | `match_score.py`，纯函数、可单测 |
| 差距分析 | 逐维度给出 当前值 / 要求值 / 差距 |
| 提升建议 | **仅当学生低于要求**时生成，避免「已超出还建议加强」的反向建议 |
| 最佳岗位推荐 | 按匹配分排序，Top1 作为「最佳匹配」展示 |

> **设计要点**：本模型衡量的是**匹配**而非**优秀**——超出岗位要求同样算偏离、同样扣分，界面上用橙色明确提示。

---

### 7. 简历输出中心（RESUME · 玫红）

**作用**：把系统内的结构化数据**提炼成可带走的成果**，是整条流水线的出口。

| 功能 | 说明 |
|---|---|
| 数据提炼 | 教育背景（GPA+专业排名+4–6 门核心课）、实习/项目要点句拆分 |
| 核心课程筛选 | 优先「学科基础 / 专业必修」，不足 4 门时放宽补齐 |
| 技能关键词提取 | 从**真实描述文本**中匹配技术关键词，**不做任何推断** |
| 能力标签 | 取能力分达阈值的维度名，**不展示具体分数** |
| 模板渲染 | `resume-templates/01-minimal.tpl.html` 极简单栏模板 |
| PDF 生成 | Edge headless 打印 A4，文字可选、字体嵌入 |

---

### 8. 系统支撑中心（SYS · 灰蓝）

**作用**：横切所有模块的配置、统计与审计能力。

| 功能 | 说明 |
|---|---|
| 规则配置 | 在线编辑 能力维度权重 / 课程能力映射 / 岗位要求（`RulesPage`） |
| 数据总览看板 | 学生总数、专业分布等统计 |
| 操作日志记录 | 所有写操作落 `audit_log`（操作人 / 动作 / 对象 / 时间） |
| 日志查询 | `GET /api/admin/audit-log` |
| 数据库初始化 | 建表 + 索引 + 字段迁移 |
| 种子数据 | 首次运行灌入专业能力配置、课程映射、培养方案、演示学生 |

## 三、模块间相关性

### 3.1 主数据流（纵向，一条主干）

```
数据导入中心 ──写入──▶ 学生数据中心 ──5类原始数据──▶ 能力评估中心 ──能力分 s_i──▶ 岗位匹配中心 ──匹配结果──▶ 简历输出中心
```

这是系统的**主干流水线**：数据从导入进来，一路被加工成能力分、匹配度，最后输出为简历。

### 3.2 标准供给（横向，注入主线的「规则」）

| 供给方 | 消费方 | 传递内容 | 性质 |
|---|---|---|---|
| 培养方案中心 | 能力评估中心 | 能力维度定义、课程→能力映射、专业权重 | **评什么、怎么评** |
| 系统支撑中心 | 岗位匹配中心 | 岗位要求值 `r_i`、重要度权重 `e_i` | **跟什么比** |
| 认证权限中心 | 全部模块 | 身份与角色 | **能不能用** |

> 主干是「**数据**」在流动，这两路是「**规则**」在注入。二者在计算模块汇合，缺一不可。

### 3.3 依赖关系速查表

| 模块 | 依赖谁 | 被谁依赖 | 依赖性质 |
|---|---|---|---|
| 认证权限 | — | 全部 | 前置网关 |
| 数据导入 | 学生数据（查重） | — | 数据入口 |
| 学生数据 | — | 导入 / 评估 / 简历 | 唯一数据源 |
| 培养方案 | — | 评估 | 标准供给 |
| 能力评估 | 学生数据 + 培养方案 | 岗位匹配 + 简历 | 计算 |
| 岗位匹配 | 能力评估 + 岗位配置 | 简历（技能标签） | 计算 |
| 简历输出 | 学生数据 + 能力评估 | — | 终端消费 |
| 系统支撑 | — | 全部（审计） | 横切 |

## 四、角色设计

### 4.1 双层角色模型

系统在 `students.role` 字段上实现**两层权限**（需求文档明确要求）：

| 角色 | 字段值 | 权限边界 | 典型使用者 |
|---|---|---|---|
| **管理员** | `admin` | 全局数据 + 配置 + 审计 | 教务/就业中心老师 |
| **普通用户（学生）** | `student` | **仅限本人**数据 | 在校学生 |

### 4.2 权限矩阵

| 功能域 | 管理员 | 学生 |
|---|---|---|
| 登录认证 | ✅ | ✅ |
| 数据总览（全局统计） | ✅ | ❌ |
| 学生检索（按学号/姓名） | ✅ 全部学生 | ❌ |
| 学生数据 增删改 | ✅ | ❌ |
| 学生数据 查看 | ✅ 任意学生 | ✅ 仅本人 |
| 批量导入 / 模板下载 | ✅ | ❌ |
| 冲突数据下载 | ✅ | ❌ |
| 批量删除 / 批量重置密码 | ✅ | ❌ |
| 规则配置（权重/映射/岗位） | ✅ | ❌ |
| 操作日志查询 | ✅ | ❌ |
| 培养方案查看 | ✅ | ✅ |
| 实践能力评估（雷达图） | ✅ | ✅ 仅本人 |
| 岗位匹配 + 提升建议 | ✅ | ✅ 仅本人 |
| 简历预览 / PDF 下载 | ✅ | ✅ 仅本人 |
| 修改本人密码 | ✅ | ✅ |

### 4.3 权限实现的三道闸

| 层级 | 位置 | 职责 |
|---|---|---|
| ① 前端路由守卫 | `PrivateRoute`（App.jsx） | 按角色分流到 `/admin/*` 或 `/student/*`，未登录跳登录页 |
| ② 后端接口鉴权 | `verify_token()` + `require_admin()` | **真正的安全边界**，与 URL 中的 student_id 比对 |
| ③ 数据层约束 | 外键 `ON DELETE CASCADE` | 删除学生自动清理其课程/竞赛/实习/项目 |

> **越权拦截示例**：学生 A 手动请求 `/api/student/B/abilities`，
> 后端比对 `payload.student_id != "B"` 且 `role != admin` → 返回 **403**。

### 4.4 前端页面分配（角色 → 页面）

**管理员端（4 个主页面 + 学生详情 8 页签）**

| 页面 | 功能 |
|---|---|
| 数据总览 | 全局统计、学生列表、检索筛选、批量操作 |
| 学生详情 | 基本信息 / 课程 / 竞赛 / 企业实习 / 项目经历 / 培养方案 / 能力评估 / 岗位匹配 |
| 批量导入 | Excel 一体化导入、CSV 分模块导入、模板下载、冲突下载 |
| 规则配置 | 能力维度权重 / 课程能力映射 / 岗位要求 在线编辑 |

**学生端（9 个页面）**

| 页面 | 功能 |
|---|---|
| 总览 | 个人统计摘要 + 基本信息 |
| 课程成绩 / 竞赛获奖 / 企业实习 / 项目经历 | 4 类数据只读展示 |
| 培养方案 | 本专业培养方案 + 毕业要求矩阵 |
| 实践能力评估 | 雷达图 + 得分来源明细 |
| 岗位匹配 | 匹配分、逐维度差距、提升建议 |
| 简历 | 预览 + PDF 下载 |

## 五、架构图绘制要点（给绘图工具）

1. **每条色带 = 一个模块**，带高一致，带内功能小方块用同色系**深色**，色带底色用同色系**浅色**。
2. 模块块（左侧）显示「中文名 + 英文代号」，如 `认证权限中心 / AUTH`。
3. 颜色按第二节表格的色值取，**不要改色相**，7 个业务模块色相彼此拉开。
4. 建议在功能架构图下方**另起一张协作关系图**（本文 3.4 节），用带标签的箭头表达数据流与标准供给。
5. 如需体现角色，可在功能块上加深浅边角标（■ 管理员可见 / ■ 学生可见 / ■ 均可）。
